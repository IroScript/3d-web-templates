# 3D ARTICLE / BLOG CARD UX TRANSFORMATION — MASTER IMPLEMENTATION PROMPT

তুমি বর্তমান **EXITO 3D Floating Cards** project-এর base design, visual language এবং 3D identity বজায় রেখে এটিকে একটি **future-ready, user-friendly 3D Article / Blog Publishing Interface**-এ রূপান্তর করবে।

বর্তমান implementation ও architecture সম্পূর্ণভাবে inspect করো। বর্তমান project specification অনুযায়ী এটি Three.js + Vanilla HTML/CSS + OrbitControls ভিত্তিক এবং বর্তমানে 25-card procedural/infinite floating matrix ব্যবহার করছে।

---

## 1. সবচেয়ে গুরুত্বপূর্ণ নির্দেশনা

**BASE DESIGN REPLACE করা যাবে না।**

বর্তমান:

* 3D floating card concept
* glassmorphism
* futuristic visual language
* lighting
* depth
* floating motion
* spatial arrangement
* embedded 3D elements
* flat-to-screen transition
* Three.js architecture

—এসবের মূল identity বজায় থাকবে। বর্তমান card-গুলো 3D floating spatial interface হিসেবে থাকবে।

কিন্তু বর্তমান design-কে **demo / visual experiment থেকে real Article Publishing UI**-তে রূপান্তর করতে হবে।

---

# 2. মূল সমস্যা সমাধান

বর্তমান system-এ card সংখ্যা procedural/infinite হলেও user-এর কাছে এটি বাস্তব article library-এর মতো ব্যবহারযোগ্য নয়।

বর্তমান 25-card matrix এবং infinite wrapping behaviour বজায় রাখার প্রয়োজন নেই যদি সেটি usability কমায়।

**Target হলো:**

> 3D থাকবে, কিন্তু ব্যবহারকারী যেন মনে না করে যে সে কোনো 3D game বা technical demo ব্যবহার করছে।

তার মনে হবে:

> “আমি একটি futuristic 3D article library ব্যবহার করছি।”

---

# 3. CARD = ARTICLE

এখন থেকে প্রতিটি floating card একটি **Article/Post entity** হিসেবে design করা হবে।

প্রতিটি card-এর মধ্যে conceptually থাকবে:

* Article cover / visual
* Category
* Title
* Short excerpt
* Author
* Publication date
* Reading time
* Tags
* Article status
* Open / Read action
* Bookmark/Favorite
* Optional metadata

Card শুধু decorative object হবে না।

**প্রতিটি card বাস্তব article-এর entry point হিসেবে কাজ করবে।**

---

# 4. HARD-CODED 3D — কিন্তু HARD-CODED UX নয়

বর্তমানে 3D cards hard-coded/procedural হওয়া acceptable।

এটি এখনই মূল API-এর সঙ্গে connect করতে হবে না।

**API integration এখন করবে না।**

কিন্তু architecture এমনভাবে তৈরি করবে যেন ভবিষ্যতে API থেকে:

```text
Article[]
```

পেলে সেই data দিয়ে unlimited cards automatically render করা যায়।

অর্থাৎ:

### এখন:

```text
Hardcoded Article Data
        ↓
Article Card Renderer
        ↓
3D Floating Cards
```

### ভবিষ্যতে:

```text
API
 ↓
Article Data
 ↓
Article Card Renderer
 ↓
3D Floating Cards
```

**3D rendering layer এবং article-data layer আলাদা রাখবে।**

API না থাকলেও interface সম্পূর্ণ usable এবং realistic demo হিসেবে কাজ করতে হবে।

---

# 5. UNLIMITED CARDS

বর্তমানে 25টি active card-এর fixed matrix রয়েছে।

এটি শুধু technical/demo limitation হিসেবে বিবেচনা করো।

Final UX-এ:

> **Article সংখ্যা unlimited হতে পারবে।**

কিন্তু screen-এ একসঙ্গে শত শত card render করবে না।

এটি অত্যন্ত গুরুত্বপূর্ণ।

### ভুল:

```text
1000 articles
↓
1000 THREE.Mesh
↓
সব screen-এ render
```

### সঠিক:

```text
Unlimited Article Dataset
        ↓
Virtualized / Visible Article Window
        ↓
Only required 3D cards rendered
```

অর্থাৎ data unlimited হতে পারে, কিন্তু active WebGL objects controlled থাকবে।

# 13. MOTION DESIGN

বর্তমান floating/drift behaviour রাখা যাবে, কিন্তু subtle করতে হবে।

বর্তমানে cards sinusoidal floating motion ব্যবহার করছে।

এটি refine করো:

### Idle

Very subtle movement.

### Hover

Slight elevation + glow.

### Focus

Card smoothly approaches user.

### Open

Card transforms into reading/preview state.

### Close

Card smoothly returns to its previous spatial position.

**কোনো abrupt movement নয়।**

---

# 14. IMPORTANT — RETURN TO STABLE STATE

এটি mandatory।

User যতই:

* pan করুক
* zoom করুক
* card খুলুক
* card close করুক
* article switch করুক
* category বদলাক

শেষ পর্যন্ত system-কে একটি **stable, predictable state**-এ ফিরিয়ে আনা সম্ভব হতে হবে।

বিশেষ করে:

```text
Explore
 ↓
Open Card
 ↓
Close
 ↓
Return to stable 3D library state
```

বর্তমান specification-এ return-to-floating-grid behaviour আছে; এই concept অবশ্যই থাকবে।

# 19. PERFORMANCE

Unlimited article data ≠ unlimited WebGL objects.

Must use:

* virtualization
* object reuse
* texture reuse
* lazy rendering
* controlled animation
* frustum awareness
* disposal
* efficient event handling

বর্তমান system shared textures ব্যবহার করে memory overhead কমানোর চেষ্টা করছে; সেই optimization philosophy বজায় রাখবে।
